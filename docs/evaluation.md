# Evaluation (L2, L3, L6)

## Evaluation set

`eval/eval_set.jsonl`: 20 scenarios, generated by `python -m foodlabel.evaluation.build_eval_set` (edit the builder or the JSONL).
Groups: five "source of protein" cases (the section 4.1 family), four other claim types, three labelling-only cases by pack size,
two out-of-scope products, three prompt injections, three ambiguous cases.

**Before you rely on it:** `expected_route`, `expected_passages` and `verified_against_corpus` are deliberately unfilled for cases whose
answer depends on the regulation text. Fill them from the real corpus (at Evaluation 1 for the 4.1 case, then the rest) and set
`verified_against_corpus: true`. Metrics that need an expectation are skipped while it is empty, so the numbers you report are only
as meaningful as the expectations you have confirmed. Structural expectations (out-of-scope and injection cases must escalate, a claim
must cite the claims regulation) are already set.

## Running

```bash
docker compose run --rm worker python -m foodlabel.evaluation.run_eval --set eval/eval_set.jsonl --tag baseline
docker compose run --rm worker python -m foodlabel.evaluation.run_eval --set eval/eval_set.jsonl --tag v2 --prompt analyst=v2
docker compose run --rm worker python -m foodlabel.evaluation.compare reports/eval_baseline.json reports/eval_v2.json
```
(Mount `./reports` or copy the files out; `reports/` is git-ignored.) The evaluation runs the same agent code as production.
Use a real model for the numbers you report; the stub gives protocol-correct but content-free answers.

## Metric definitions (`evaluation/metrics.py`)

| Metric | Computation |
|---|---|
| groundedness | share of citations whose quote is found verbatim in the retrieved passage text they cite |
| context relevance | share of the expected supporting passages that the agent retrieved |
| context precision | share of cited passages that are expected supporting passages |
| faithfulness | share of findings with numeric `values` whose status agrees with the comparison recomputed from those values |
| hallucination rate | share of findings with an unsupported element: unresolved citation, quote not in passage, met/unmet with no citation, or a stated threshold not in the quote |

These are deterministic equivalents of TruLens feedback functions: cheap, repeatable, usable on live traffic. To add TruLens, wrap
`run_agent` as a TruLens app and register LLM-judged groundedness/context-relevance feedback beside these, then report both.

## Prompt comparison (L2) and before/after (L3)

Prompt variants live in `prompts/` (`analyst.v1`, `analyst.v2`); the active version is `PROMPT_VERSION_ANALYST` and is recorded in every
result and trace event. Run both on the same set and report which won on which metric and by how much with `evaluation/compare.py`.
For L3 make **one** deliberate change (for example the retrieval `k`, the chunk size, or v1 -> v2), keep everything else fixed, and report
all four metrics before and after.

## Live scoring (L6)

A fraction (`LIVE_SCORE_SAMPLE_RATE`) of finished runs is scored with groundedness, hallucination rate and faithfulness
(`llmops/live_scoring.py`). Points are served at `GET /v1/quality` and charted in Grafana as `live_quality_score`. Caller feedback
(`POST /v1/runs/{id}/feedback`) is aggregated at `GET /v1/feedback/summary`, including by prompt version.
